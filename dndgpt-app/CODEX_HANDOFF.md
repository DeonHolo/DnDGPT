# Development handoff

Public source checkpoint: application version 1.0.17, rules edition 1.0.

Prioritize ChatGPT as GM, one reusable dashboard, batched state updates and reusable Python rolls. Preserve the full rulebook and hardener. Source integrity tests distinguish authorized amendments from unrelated edits.

Run the Python suite before packaging. Exercise presentation changes through the disposable host harness, then verify the actual target ChatGPT client. A local page or simulator does not prove a live MCP App connection or persistent client surface.

The public App mapping is an example. Configure your own `.app.json` before creating a usable package. Personal runtime, tunnel credentials, Windows startup setup, live acceptance records and actual saves are not part of this repository.

Do not use development work as authorization to start, resume, import, roll for or mutate a player's game. Keep real account tests isolated from disposable fixtures.

Standard new chat games use `app/standard_rules.py`: HP = 45 + 3 × STR, MP = 75 + 5 × INT. The profile marker distinguishes new standard games from older saves and explicit custom rulebooks. Class confirmation checks the required class-native roles, including two Utilities for Unique. This checks recorded kit counts; the GM still follows the complete hardener to judge creativity, flavor and distinct functionality.

`app/presentation.py` embeds the credited public-domain WebP paintings into the MCP HTML. Keep `app/assets/` in source deployments and packaged releases. UI tests use the disposable host harness; no real player campaign should be seeded into fixtures or screenshots. Dashboard polling is still unchanged.
